## Scope

After a live neighbourhood switch from Cheats, the road banner and the neighbourhood pill still
name the old neighbourhood. They name the chosen one, with its place as the slot the walk is now
in.

## Criteria

- After the switch, the banner and the pill name the chosen neighbourhood and the current slot,
  and they stay correct through the rest of the walk and on resume.

## Decisions

- Cause: a live switch replaces the route's current slot and keeps `zoneIndex`, and both views
  cached on the slot alone. `ZoneBanner.show` (`src/scenes/run/roadBanners.ts`) skipped a show
  for the slot it last showed, so the switched zone's start drew no banner, and the old one stayed
  up while it lasted. The pill (`createHudChrome` in `src/hud/dom/hudChrome.ts`) redrew only when
  the slot or the debuff count changed, so it kept the old name ("High Park 1 of 4").
- Fix: the banner shows at every zone start, a switch's included (the switch path's deferred plan
  still starts the zone in `planDueZone`), replacing any banner still up. The pill's redraw key is
  its drawn name and count with the debuff count, so the name follows the route slot the walk is
  in. Both read `currentZone` and `zoneIndex`, so the next zone and a resumed walk, whose resume
  point is the switched zone's start, name the same neighbourhood and slot.
- The worker planning path (adw-0247) is unchanged.
