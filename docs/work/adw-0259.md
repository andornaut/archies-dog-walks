## Scope

The eleven ranked steps of the adw-0258 structure plan
(`game-coordinator/var/handoffs/games/archies-dog-walks/tech/proofs/adw-0258/report.md`), each
landing on its own with behaviour unchanged:

1. One import check that places every module in a band of the cross-game skeleton and fails on a
   cycle, a wrong-direction import or an unplaced module, with a known-violations table that only
   shrinks.
2. Delete dead code and move misplaced test fixtures.
3. Break the model cycles between rules, state and save.
4. Fix the foundation and geometry imports.
5. Replace scene class types with small shared types and port interfaces.
6. Fix the small cycles.
7. Move build code out of shipped folders.
8. Move the pieces `home` and `hud` share into lower folders.
9. One public entry per area, lowest layers first.
10. Move effects to the edges.
11. Split the large files.

Steps that touch work in flight wait for it: UI steps for adw-0255 and adw-0257, planner steps for
adw-0254. The cross-game requirements are game-coordinator:gc-0028 and game-coordinator:gc-0029.

## Criteria

- Every import points down the named layers; groups in the same layer do not import each other.
- No runtime import cycle; type-only imports point down and may form cycles only within one band.
- Each step proves unchanged behaviour: type check and tests, pixel-identical captures for views,
  and the planner acceptance batch for generation.

## Decisions

- Strict layers: groups in the same layer may not import each other (user, 2026-11-25).
- The import check is temporary in every game: it runs until the known-violations table is empty,
  then it is removed and ESLint guards the layers (user, 2026-11-25).
- Archie maps its directories onto the cross-game layer skeleton, and its pure interface geometry
  and text placement (`ui`, `ui/modal`) move above the model as presentation (user, 2026-11-25).
- Authored data files are imported directly, as in the cross-game skeleton; every other area has
  one public entry (user, 2026-11-25).
- Data ids move into explicit lists in `data/ids.ts`. Gameplay agreed (2026-11-25): Gameplay owns
  the lists and Tech their shape and the match test; lists keep their table's order where order
  means something and are alphabetized otherwise; the test fails on an id missing from either side;
  no id is renamed.
- `src/dev/` becomes `src/cheats/`; build-time modules move under `src/tools/`; sparse obstacle
  weights stay out of scope (user, 2026-11-25).
- The older `CONTEXTS` lint rules retire; the source bands are the one layer rule (user,
  2026-11-25).
- The crash screen installs after the modules its area entries re-export, which only declare
  values; no boot group or crash exemption (user, 2026-11-26).

## Outcome

Steps 1 to 8 are done, and ESLint guards the layers in place of the import check: `BANDS` in
`eslint.config.mjs` places every module of `src/` but the tests in a group of the cross-game bands,
and a module no group holds fails. `import-x/no-restricted-paths` holds each group outside
`src/testing/` to its own group and lower rows, type-only imports included, so nothing shipped
imports Support, and `import-x/no-cycle` refuses runtime cycles. Step 9 gives each area one public entry, which ESLint enforces. Step 10 moves browser audio, save storage, cheat setup and the zone planner worker into
Platform. Lower bands take reporting and storage through explicit ports and reject global effects.
Step 11 splits the 25 audited production files by responsibility. Home owns the Shop and
shared page rendering, with reusable native surface and scroll machinery in UI. The runner
separates planning, certification and audit from private preparation, search and board helpers.
Game data, public contracts and player-facing layout are preserved.
