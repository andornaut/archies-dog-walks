## Scope

A live neighbourhood switch from Cheats plans the new road on the main thread, which holds the
page for 0.2 to 1.3 seconds after the selection shows. Plan it without blocking input or
painting, keeping the planner's output identical.

## Criteria

- After a live neighbourhood switch the page keeps painting and answering input while the road
  is planned, and the walk resumes on the same road the current planner produces.
- The planner contract and its acceptance results are unchanged.

## Decisions

- Cause: a live neighbourhood switch and a fork's path both plan the next zone in the press's
  task (`jumpToNeighbourhood` and `chooseShownCard` in `src/runner/session.ts`). Local headless
  Chromium at 360x608 measured one 294 to 454ms main-thread task for a switch and 1216ms for a
  fork's path, the page frozen for as long.
- Fix: a module worker plans the zone (`src/runner/zonePlanner.ts`, `zonePlanWorker.ts`). The
  planner is a pure function of the game data, the seed and the walk, its streams named from the
  seed (`spawns-<zone>`, `movers-<zone>`), so the worker's plan (`planZoneFromSeed`) is the plan
  the step makes. Slicing the planner's search across frames would rewrite its search loop, and
  planning likely neighbourhoods ahead would plan every one the player might press, from run state
  that cheats and forks change.
- A fork's choice or a neighbourhood cheat in the run scene defers the plan (`ZonePlanning`): the
  zone starts at the press (banner, music, resume point and checkpoint), and the walk holds
  (`runPause`) until `withZonePlan` takes the plan. A plan for a session since replaced is dropped,
  and the latest request wins. Another cheat pressed while a plan is still to come plans it on the
  page first, so cheats apply to the planned walk. Without a worker, or once it fails to load, the
  page plans the zone itself.
- The simulator, replays, resumed walks and a walk's first zone plan in the step, unchanged; a
  walk's first zone is planned as the run scene starts, before the walk's first frame.
- Vite emits the worker as a hashed file under `/assets/` that the game's chunk references, so the
  build's precache manifest lists it and the service worker serves it offline; `worker-src 'self'`
  allows it.

## Outcome

Ready on branch `adw-0247-async-plan`. Unit tests (`src/runner/zonePlanner.test.ts`) check that a
switch on seeds 1, 7 and 2026 in route slots 0, 2 and 3, and a fork's path, planned through a
copying worker or after a worker failure, give the session the step makes byte for byte, and that
its next step matches. Local headless Chromium at 360x608, from the press for 3s: a switch's
longest main-thread task fell from 294 to 454ms to at most 68ms (none above 50ms in one of
four presses), its longest frame gap from 283 to 467ms to at most 67ms; a fork's path fell from a
1216ms task and 1233ms gap to none above 50ms and a 33ms gap. The walk resumed in the pressed
neighbourhood each time, and offline after install the worker loaded from the precache with the
same results.
